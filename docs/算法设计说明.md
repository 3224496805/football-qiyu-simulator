# 足球奇域模拟器 · 算法设计说明（v0.1）

> 基于《奇域事件优先级-需求笔记》第四节默认假设。所有公式/伪代码以最终确认的需求为准。

## 0. 记号约定

- 实体集合 `E = {e₁, e₂, …}`（球员A、球员B、球……），球也是一等实体。
- 状态类型集合 `S`（无球 / 持球 / 蓄力 / 射门·激活……）。
- 全局状态 `g ∈ S^E`：从实体到状态类型的映射（组合状态）。
- 事件集合 `X`（传 / 掉 / 射 / 蓄力条更新 / 拿 / 激活射门技能 / 关闭射门技能……）。

## 1. 数据模型

### 1.1 个体状态逻辑图（单实体）

```
G_e = (V_e, A_e)
  V_e ⊆ {e} × S              // 该实体可出现的状态
  A_e ⊆ V_e × X × V_e        // 转换边
```

每条边 `a = (v, x, v')` 携带：

```
a = {
  id, event: x,
  from: v, to: v',
  condition: CondTree,       // 布尔表达式树（见 1.2）
  effects: [Effect],         // 执行该转换时对其他实体/全局量的写操作
  params: {
    basePriority: int,       // 手动基础优先级（默认预置：传7 掉6 射5 蓄力更新4 拿3 激活2 关闭1）
    cooldown: int,           // 触发后冷却 tick 数
    countLimit: int,         // 最大触发次数（∞ 表示不限）
    structWeight: float      // 结构权重，默认 1.0
  }
}
```

### 1.2 条件树

```
CondTree ::= Atom | AND(CondTree…) | OR(CondTree…) | NOT(CondTree)
Atom ::= SelfState(s) | HolderIs(e) | TimerGE(t) | DistLT(e, d) | Flag(f) | …
```

求值 `eval(cond, g, env) → bool`，env 含计时器、距离、自定义 flag。

## 2. 图变换算法（个体图 → 总状态逻辑超图）

### 2.1 粘合（glue）

输入：图 `G₁, G₂`，粘合映射 `M: S₁ ⊇ D → S₂`（同语义状态类型，如"无球"）。

```
Glue(G₁, G₂, M):
  for (s₁, s₂) in M: 建立等价类 [s₁~s₂]
  V = V₁ ∪ V₂ / ~            // 商集：等价类合并为一个共享节点
  A = { ([v], x, [v']) : (v,x,v') ∈ A₁ ∪ A₂ }   // 边的端点替换为等价类
  return (V, A)
```

用途：把多个实体的"无球/持球"粘成全局球归属节点，表达互斥资源。

### 2.2 复合（compose，同步积）

输入：图 `G₁, G₂`，同步事件对 `Sync ⊆ X₁ × X₂`（如 (A传, B接)）。

```
Compose(G₁, G₂, Sync):
  V = V₁ × V₂                        // 组合状态（按需惰性展开，防状态爆炸）
  A = 静默边：{ ((u,v), x, (u',v)) : (u,x,u') ∈ A₁, x 不同步 }
            ∪ { ((u,v), y, (u,v')) : (v,y,v') ∈ A₂, y 不同步 }
            ∪ 同步边：{ ((u,v), (x,y), (u',v')) : (u,x,u') ∈ A₁, (v,y,v') ∈ A₂, (x,y) ∈ Sync }
```

说明：默认只做**同步积**，即仅同步事件联合触发；若用户要求全笛卡尔积，把"不同步"限定去掉即可。

### 2.3 多实体状态超图与总超图

- 超边：`h = (T, x, T')`，`T, T' ⊆ V` 为端点**集合**（≥2 个实体节点），语义 = 联合事件一次改写多个实体（"A 传球给 B"：T={A持球, B无球} → T'={A无球, B持球}，球的 Holder 同步改写）。
- 构造：对每个实体图 `G_e` 先做 glue 得到共享资源节点；再按 Sync 做 compose；把跨实体 effects 显式化为超边；得到**总状态逻辑超图** `H*`。
- H* 保留实体维度（节点带 entityId 标签）；投影视图 = 按实体着色/折叠，仅为展示层。

## 3. BFS 事件搜索树算法

多源 BFS 从初始全局状态 `g₀` 展开。有环图必须 visited 判重（记录 (节点, 事件序列哈希) 防同层重复扩展）。

```
BFS-EventTree(H*, g₀):
  Q ← [g₀]; layer(g₀) ← 0; visited ← {g₀}
  L(x) ← {}                     // 事件 x 出现的层数集合
  Tree ← 根 g₀
  while Q 非空:
    g ← Q.pop_front()
    for 每个在 g 上可触发的边/超边 a=(g, x, g'):
      L(x).add(layer(g) + 1)
      if g' ∉ visited: visited.add(g'); layer(g') ← layer(g)+1; Q.push(g'); Tree 加子节点
      else: Tree 加一条回指边（标记成环，仍记录 L(x)）
  return Tree, L
```

要点：事件 x 在 BFS 后处于**不同层** → 用 `L(x)` 聚合（见 §4）。

## 4. 优先级评分算法

### 4.1 层数聚合（三种可切换，默认 max）

```
layerScore(x) = max L(x)              // 默认
              | mean L(x)             // 平均
              | Σ_{b∋x} w_b · layer_b // 按分支权重加权（w_b = 分支上 structWeight 之积）
```

### 4.2 修正项

```
cycleFactor(x)   = 0.5   若 x 位于环上（Tree 回指边标记），否则 1.0
reachFactor(x)   = 1 + 0.1 · outReach(x)     // outReach = 从 x 可达的不同事件数
```

### 4.3 最终优先级分与全序

```
score(x) = layerScore(x) · cycleFactor(x) · reachFactor(x) + α · basePriority(x)
                                                       // α 默认 0.5，手动微调幅度
```

排序规则（确定性全序）：`score` 降序 → 同分比 `basePriority` 降序 → 再同分比 `structWeight` 降序 → 再同分按事件名字典序。

输出：事件优先级总表 + 每个事件的 `L(x)`、修正明细（界面可展开）。

## 5. 模拟器 tick 算法（100ms，可加速/单步）

```
Simulate(H*, g₀, T):
  g ← g₀; timer[entities] ← 0; log ← []
  for t = 1..T:
    fired ← {}
    for e in E（并行收集，互不争抢）:
      cands[e] ← { a ∈ 出边(g,e) : eval(a.condition, g, env) 且 cooldown/count 满足 }
      // 矛盾检测：两个实体候选写同一资源（如同抢球）
      conflicts ← 按目标资源分组，组内成员 >1 的组
      for 每组冲突: 按 score 排序，仅第一名入 fired（其余记为"被抑制"）
    for a in fired（按 score 降序执行）:
      if a 为超边: 校验全部端点状态仍匹配（乐观锁），不匹配 → 记矛盾，触发回溯补偿
      apply(a.effects); log.append(t, a); 更新 cooldown/count/timer
    g ← g'
  return log, 矛盾记录
```

### 5.1 回溯补偿（高延迟补偿，可选开关）

- 记录最近 N tick 的"最高优先级变量序列"（对应笔记"逻辑记忆"）。
- 发现矛盾（如延迟导致 掉球、传球 先后都触发）：回滚到分歧点，**采用高分支**（笔记原则：状态倾向向高优先级发展；最高优先级之后回到更新后状态）。
- 副作用提示：界面标注"球掉了又被传走"类负面效果计数。

## 6. 参数调整建议算法

目标：矛盾率 ↓、合作事件（传/配合）触发率 ↑，且不破坏既有全序稳定性。

```
Suggest(H*, 模拟统计):
  建议 ← []
  for 矛盾记录 c:
    loser ← c 中 score 较低的事件
    建议.append("提高 {loser}.basePriority +1 或缩短其 cooldown，预期矛盾率 ↓{est}%")
  for 合作事件 x（传/接…）:
    if 触发频率 < 目标阈值 τ: 建议.append("提高 {x}.structWeight → layerScore 提升 {Δ}")
  for 死循环分支（环上事件）:
    建议.append("对 {x} 增加 countLimit 或 cooldown，打破热循环")
  return 建议（按预期改善排序）
```

`est%/Δ` 通过"应用建议 → 重跑 BFS + 短模拟（1000 tick）对比"估计。
