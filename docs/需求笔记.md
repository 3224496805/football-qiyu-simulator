## 二、用户确认的需求决策（v0.2）

### 图与事件模型

1. **转换边 = 事件（带条件）**：条件由千星沙盒的事件节点给出，事件进入**事件队列**。
2. **优先级的用途**：短时间内事件队列中两个**冲突事件**并发时，用优先级决定**哪个只执行一次**（另一个被抑制）。
3. **状态节点公用**：状态（无球/持球/…）是公用类型，挂在不同角色实体上 → 节点实例 = (实体, 状态)。
4. **粘合（glue）**：相同状态节点合并、有向边随之粘合。例：断球与传球都是"持球→无球"变化。但超图中二者表达不同：
   - 传球后，队内循环出现**临时虚拟队友实体**进入"拿球"状态（= 球权在队内），必须经过该临时状态转接到队友手上；
   - 若队友不满足拿球事件，队内拿球状态转为**队外自由状态**，球被随机争抢。
5. **复合（compose）= 状态叠加（图替换）**：把状态图中每个点换成一个完整状态图。例：球状态图 × 位置状态图，两个维度互不影响。（注意：不是同步积/笛卡尔积，而是分层图替换。）
6. **超边 = 多实体联合事件**。
7. 总超图**保留实体维度**。

### BFS 与优先级算法（重要修正）

8. **BFS 起点 = 无球**（单一初始状态）。
9. **决胜规则 = 优先级排序**；相同优先级、不同实体 → 按事件默认排序（确定性兜底）。
10. （原 Q9 聚合规则）→ 被第 11 条的新语义取代，见下。
11. **优先级排序的目的（核心）**：尽量避免游戏状态陷入**短的死循环**，让全局状态尽量处于**大的循环**中。
    - 因此**不是"层数越深优先级越高"**，而是：**通往深层路上的事件都高优先级**；
    - 推论：处于短环/死循环上的事件应被压低，把状态"推"向主大循环。

### 网站功能与交付

12. **可视化编辑**：实体类型有玩家、球，后续可扩展；玩家总数上限 8 人、两个阵营，**默认每边 3 人（共 6 人）**，数量可调。
13. **第一期先做静态计算**（BFS + 优先级 + 参数建议），动态模拟后期再加。
14. **参数主要是位置状态图的参数**：如玩家的位移技能（位移距离、冷却等）。

## 三、项目状态逻辑总结（用户提供，v0.2 新增）

逻辑域（每个域一张状态图，复合成总图）：

| 逻辑域 | 内容 | 复杂度 |
|---|---|---|
| 球逻辑 | 球权归属：持球/无球/队内拿球（虚拟队友实体）/队外自由/被争抢 | 中 |
| **位置逻辑** | 玩家位置状态变化：移动、位移技能等 | **最复杂** |
| 控制逻辑 | 控制状态变化 | 中 |
| 血量逻辑 | 血量状态、伤害节点、掉球触发 | 中 |

**跨域依赖（事件级联）**：
- 射门状态、血量攻击节点都以**位置状态变化作为事件触发前提**；
- 角色的**伤害事件**在满足位置前提时，可改变**他人**的血量状态（跨实体超边）；
- 血量低于阈值的状态变化 → 触发**掉球事件**（血量逻辑 → 球逻辑的级联）；
- **事件本身可以由状态变化触发**（事件→状态→事件的链式传导）。

**需要平衡的参数清单**：
- 伤害大小参数、血量参数（含掉血阈值）、位移距离（及位移技能冷却等位置参数）。

## 四、算法设计修订（对应第 11 条新语义）

> 旧版"层数越多优先级越高 + max 聚合"作废，替换为：

1. BFS 从"无球"出发，标记每个事件的层数集合 L(x)。
2. **主循环识别**：Tarjan SCC 找出最大强连通分量（主大循环）；短环单独标记。
3. **路径加分**：事件 x 若位于"起点 → 主循环"的可达路径上（或主循环本身）→ 高分；
   形式化：`pathScore(x) = 1 − dist(x 到主循环的最近距离) / D`（D 为图直径），在主循环上 = 1。
4. **短环惩罚**：x 位于长度 < τ 的环上（τ 默认 4）→ ×0.3。
5. **冲突裁决**：事件队列同 tick 冲突 → 按 score 降序，只执行第一名（其余记"被抑制"）；
   同分 → 事件默认排序（内置逻辑链序：传＞掉＞射＞蓄力更新＞拿＞激活＞关闭）。
6. **复合语义**：四个逻辑域互不影响，各域独立 BFS 后合并排名。
7. **参数建议**：围绕待平衡参数（伤害/血量/位移距离），目标 = 消灭短环、把流量赶入主循环 + 冲突率下降；输出"参数值建议 + 调整前后对比（环结构变化、各事件优先级变化）"。

## 六、需求闭环（v0.3 开工版）

- 网站名：足球奇域模拟器；React + TS 本地应用，Kimi Work 预览。
- 实体：玩家（默认 3v3 共 6，可调至上限 8，两阵营）+ 球 + 临时虚拟队友实体（传球转接）。
- 逻辑域状态图：球 / 位置（最复杂）/ 控制 / 血量；复合 = 图替换式叠加；粘合 = 同状态节点合并（含虚拟队友转接语义）；超边 = 多实体联合事件；总超图保留实体维度。
- 优先级：BFS 起点=无球；主大循环识别；通往主循环路径上的事件高分；短环惩罚；冲突时只执行最高优先级事件一次；同分按默认序（传＞掉＞射＞蓄力更新＞拿＞激活＞关闭）。
- 参数平衡：伤害大小、血量（含掉血阈值）、位移距离/冷却；建议面板给出调整值 + 前后对比。
- 技能模板：伤害事件模板、位移事件模板（自由设计，未接入游戏）。
- 存储：localStorage 多方案隔离 + JSON 导入导出；GitHub 公开托管。
